# ArborGuard System Documentation

ระบบตรวจสอบและแจ้งเตือนเหตุการณ์ผิดปกติของต้นไม้ (ArborGuard) พัฒนาด้วย Next.js, Express, Socket.IO, SQLite และรองรับการสื่อสารสองทางผ่านทั้ง HTTP REST API และ MQTT (HiveMQ Cloud)

---

## 1. การติดตั้งและเริ่มต้นระบบด้วย Docker

สำหรับผู้ใช้งานที่ได้รับชุดอิมเมจและไฟล์ติดตั้ง ให้เตรียมไฟล์ทั้ง 3 ไฟล์ให้อยู่ในโฟลเดอร์เดียวกัน:
- project-all-in-one.tar (Docker image bundle)
- docker-compose.yml
- .env (กำหนดค่าตัวแปร เช่น TUNNEL_TOKEN)

### คำสั่งควบคุมระบบ

1. โหลด Image เข้าสู่ Docker:
docker load -i project-all-in-one.tar

2. เริ่มต้นการทำงานของระบบในพื้นหลัง:
docker compose up -d

3. ตรวจสอบสถานะการทำงาน:
docker compose ps

4. ตรวจสอบบันทึกการทำงาน (Logs):
docker compose logs -f
docker compose logs -f tunnel

5. สั่งหยุดการทำงาน:
docker compose down

## 2. HTTP REST API Reference

### 2.1 แจ้งเตือนเหตุการณ์ (Trigger Alert)
ใช้เมื่อโหนดตรวจพบเหตุการณ์ผิดปกติ เช่น ต้นไม้ล้มหรือเอียง (ระบบจะไม่บันทึกซ้ำหากโหนดนั้นมีสถานะ active ค้างอยู่)

Endpoint: POST /api/alert
Headers: Content-Type: application/json

Request Body:
{
  "node_id": "NODE_KPS_01",
  "event_type": "ต้นไม้ล้ม",
  "lat": 14.0245,
  "lng": 99.9732
}

คำอธิบายฟิลด์:
- node_id (String): รหัสประจำตัวของบอร์ดเซนเซอร์
- event_type (String): ข้อความระบุประเภทเหตุการณ์
- lat (Float): พิกัดละติจูด
- lng (Float): พิกัดลองจิจูด

Response Success (201 Created):
{
  "success": true,
  "id": 1
}

Response Conflict (409 Conflict):
{
  "message": "Alert already active for this node"
}

---

### 2.2 ลงทะเบียนอุปกรณ์ (Register Device)
ใช้บันทึกตำแหน่งติดตั้งประจำของอุปกรณ์เข้าสู่ระบบ

Endpoint: POST /api/regist_devices
Headers: Content-Type: application/json

Request Body:
{
  "node_id": "NODE_KPS_01",
  "lat": 14.0245,
  "lng": 99.9732
}

Response Success (201 Created):
{
  "success": true,
  "id": 1
}

Response Already Registered (200 OK):
{
  "success": true,
  "message": "Device already registered",
  "device": {
    "id": 1,
    "node_id": "NODE_KPS_01",
    "lat": 14.0245,
    "lng": 99.9732
  }
}

---

### 2.3 เคลียร์สถานะการแจ้งเตือน (Clear Alert)
ใช้ปรับสถานะเหตุการณ์ของโหนดที่ระบุจาก active เป็น resolved

Endpoint: POST /api/clear
Headers: Content-Type: application/json

Request Body:
{
  "node_id": "NODE_KPS_01"
}

Response Success (200 OK):
{
  "success": true,
  "cleared_count": 1
}

---

### 2.4 ดึงข้อมูลสถานะและอุปกรณ์ (Data Query)

- GET /api/devices: ดึงรายชื่ออุปกรณ์ทั้งหมดที่ลงทะเบียนในระบบ
- GET /api/active: ดึงรายการเหตุการณ์ที่ยังคงมีสถานะ active
- GET /api/nonactive: ดึงรายการประวัติเหตุการณ์ที่แก้ไขแล้ว (status != active)
- GET /api/alerts_all: ดึงรายการประวัติเหตุการณ์ทั้งหมด

## 3. MQTT Broker Integration

ระบบเชื่อมต่อไปยัง HiveMQ Cloud ผ่าน TLS (พอร์ต 8883) เพื่อรับข้อมูลจากอุปกรณ์ IoT โดยตรง

- Broker URL: mqtts://8ef1f963d1b148208842c37f76971b73.s1.eu.hivemq.cloud:8883
- Port: 8883 (MQTTS - SSL/TLS)

### หัวข้อรับข้อมูล (Subscribed Topics)

1. arborguard/alert
หน้าที่: สร้างการแจ้งเตือนเหตุการณ์
Payload:
{
  "node_id": "NODE_KPS_01",
  "event_type": "ต้นไม้ล้ม",
  "lat": 14.0245,
  "lng": 99.9732
}

2. arborguard/regist_devices
หน้าที่: ลงทะเบียนอุปกรณ์ใหม่เข้าสู่ฐานข้อมูล
Payload:
{
  "node_id": "NODE_KPS_01",
  "lat": 14.0245,
  "lng": 99.9732
}

3. arborguard/clear
หน้าที่: เคลียร์สถานะแจ้งเตือนของอุปกรณ์
Payload:
{
  "node_id": "NODE_KPS_01"
}

## 4. WebSocket Real-time Events (Socket.IO)

ระบบส่งสัญญาณอัปเดตหน้า Dashboard แบบทันทีผ่าน Socket.IO (Path: /socket.io/):

- new_alert: ส่งข้อมูลอ็อบเจกต์เหตุการณ์ใหม่เมื่อเกิดการแจ้งเตือน
- new_devices: ส่งข้อมูลอ็อบเจกต์อุปกรณ์ใหม่เมื่อมีการลงทะเบียน
- alert_cleared: ส่งข้อมูลรหัสโหนดที่ถูกเคลียร์สถานะ ({"node_id": "..."})
